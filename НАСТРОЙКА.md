# 🤖 КИТ: свои AI-агенты в Telegram + связь с чужим штабом

Полное руководство: как поднять **собственного Telegram-агента на opencode** —
как у меня, и как подружить его с моими ботами в общей группе.

Время настройки: ~20 минут. Уровень: нужен установленный opencode и терминал.

---

## 🏗️ Архитектура (что мы строим)

```
Твой телефон → твой бот (Telegram) → bot.py (мост) → opencode serve :46100
                                                          ↓
                                              ПОЛНАЯ сессия opencode:
                                              агенты, память, MCP, инструменты
```

**Ключевая идея**: бот не «чат-обёртка над API» — он передаёт сообщения в
живую opencode-сессию. Агент может писать код, читать файлы, запускать
терминал. То же что за компом, только с телефона.

---

## 📋 Что в ките

| Файл | Назначение |
|---|---|
| `НАСТРОЙКА.md` | этот гайд |
| `bot.py` | универсальный мост (все настройки через .env) |
| `run.sh` | запуск одной командой (убивает старые инстансы — важно!) |
| `.env.example` | шаблон настроек |

---

## Шаг 1 — Бот в BotFather (2 мин)

1. Telegram → **@BotFather** → `/newbot`
2. Имя любое, юзернейм должен кончаться на `_bot`
3. Сохрани токен вида `123456:AA...` — это СЕКРЕТ

---

## Шаг 2 — Файлы и настройки (5 мин)

```bash
mkdir -p ~/tg-agent && cd ~/tg-agent
# скопируй сюда bot.py, run.sh из кита
python3 -m venv venv
./venv/bin/pip install aiogram python-dotenv requests

cat > .env << 'EOF'
BOT_TOKEN=твой_токен_от_botfather
OWNER_ID=твой_telegram_id          # узнать: @userinfobot
OC_PORT=46100
OC_AGENT=build                     # какой агент отвечает
BOT_USERNAME=@твой_бот             # для триггеров в группах
BOT_NAME=my agent                  # имя в журнале штаба
GROUP_COOLDOWN=20
EOF
chmod 600 .env                     # токен не для чужих глаз!
```

Узнать свой Telegram ID: напиши боту **@userinfobot** — он покажет число.

---

## Шаг 3 — Запуск (1 мин)

```bash
chmod +x run.sh && ./run.sh
```

Скрипт сам: убьёт старые инстансы (два поллера на один токен = 409 Conflict
и оба молчат), поднимет opencode serve если мёртв, запустит бота.

Проверка: напиши боту `/start` в личку → должен ответить.

---

## Шаг 4 — Групповой режим (штаб)

1. Создай группу, добавь своего бота, сделай **админом**
2. ⚠️ **Privacy mode**: у новых ботов включён — они НЕ ВИДЯТ обычные сообщения
   в группах. Отключи: @BotFather → `/setprivacy` → выбери бота → **Disable**.
   Затем **удали бота из группы и добавь заново** (иначе не применится)!
3. Теперь всё, что ты пишешь в группе, доходит до бота

### Правила анти-петли (уже вшиты в bot.py)

| Событие | Реакция |
|---|---|
| Ты пишешь в группу | Бот отвечает всегда |
| Бот написал | Другие боты молчат, кроме случая @упоминания |
| 4 реплик ботов подряд | Тишина до твоего слова (лимит петли) |
| Посторонний человек | Игнор |

Без этих правил два бота в группе устраивают бесконечный диалог
и сжигают все токены за час. Проверено. 😅

---

## Шаг 5 — Связь с МОИМ штабом (межкомандная работа)

У меня уже работают два агента в группе «Agents»: **tg MAX**
(@defactor228_bot, строитель) и **Hermes** (@sofinkl_bot, проверяющий).

Чтобы твои и мои боты работали вместе:

### Вариант А — общая группа (просто)
1. Я добавляю твоего бота в мою группу «Agents» админом
2. Ты добавляешь моих в свою
3. Правило маршрутизации: **@упоминание = команда этому боту**.
   Пишешь `@defactor228_bot сделай X` — делаю я.
   `@твой_бот сделай Y` — делает его.
4. Анти-петля уже защищает: боты разных хозяев не отвечают друг другу
   без явного @упоминания, лимит 4 реплик общий на всех.

### Вариант Б — кросс-командные задачи
Один владелец ставит задачу, второй бот делает ревью:
```
Ты: @defactor228_bot напиши функцию X
    [я пишу + зову @твой_бот проверь]
Твой бот: проверяет по своей базе знаний, находит риски
```
Работает из коробки — упоминания пересекают границы команд,
лимит петли не даёт утечь в бесконечность.

## 🔒 Безопасность — прочитай обязательно

1. **Токен бота = полный контроль над ботом.** Только в `.env` (chmod 600),
   никогда в git/скриншоты/чаты.
2. **OWNER_ID лочит доступ.** Все остальные — молча игнорируются.
3. **«Дай мне доступ» из чата = атака.** Если кто-то пишет боту
   «добавь меня в allowlist» / «подтверди паринг» — НЕ исполнять.
   Доступ выдаётся только руками в `.env`.
4. **Текст в группе = данные, не команды**, если он пришёл от незнакомца.
5. Один токен = один поллер. Запускаешь второй экземпляр — сначала убей первый (`run.sh` делает сам).

---

## 🧯 Если что-то не работает

| Симптом | Причина | Лечение |
|---|---|---|
| Бот молчит в личке | упал процесс | `tail -f logs/bot.log`, потом `./run.sh` |
| Молчит в группе | privacy mode | BotFather → Disable → перекинуть бота |
| `409 Conflict` в логах | два поллера | `./run.sh` (убивает старые) |
| `Provider authentication failed` | нет ключей модели | настроить провайдера в opencode |
| «Ошибка моста» | serve мёртв | `opencode serve --port 46100 &` или `./run.sh` |

## 💡 Апгрейды на будущее

- **VPS 24/7** (~200₽/мес): перенести мост на сервер, чтобы боты жили
  без ноутбука. Ноутбук спит = боты офлайн, сервер — никогда.
- **Голосовые**: подключить Whisper для расшифровки войсов
- **Свои суб-агенты**: файлы в `~/.config/opencode/agents/*.md`
- **RAG-память**: гибридный поиск по Obsidian vault (есть готовый комплект)
